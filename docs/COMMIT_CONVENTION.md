# 커밋 메시지 규칙

GitHub 커밋 목록에서 **언제(커밋 일시)** 와 **무엇이 바뀌었는지(커밋 메시지)** 를 한눈에 읽을 수 있도록, 모든 커밋은 아래 규칙을 따릅니다.

## 1. 형식

```
[분류] 무엇을 했는지 한 줄 요약 (50자 이내)

- 바뀐 내용 1
- 바뀐 내용 2

이유: 왜 바꿨는지 한두 문장
```

- **첫 줄(제목)** 만 GitHub 커밋 목록에 보입니다. 첫 줄만 읽어도 무엇이 바뀌었는지 알 수 있게 씁니다.
- 제목과 본문 사이는 **한 줄 비웁니다.**
- 본문은 선택이지만, 파일을 여러 개 고쳤거나 이유가 중요하면 꼭 씁니다.
- 커밋 일시는 Git이 자동으로 기록하므로 메시지에 날짜를 적지 않습니다.

## 2. 분류 태그

| 태그 | 언제 쓰나요 | 예시 |
|---|---|---|
| `[기능]` | 새 기능 추가 | `[기능] 감정 선택 창에 '불안' 항목 추가` |
| `[수정]` | 버그 고침 | `[수정] 추천 책이 두 번 표시되는 문제 해결` |
| `[개선]` | 기존 기능을 더 좋게 (동작 변화 있음) | `[개선] 챗봇 답변 속도 향상` |
| `[디자인]` | 화면 모양·스타일만 변경 | `[디자인] 책 카드 모서리를 둥글게 변경` |
| `[내용]` | 책 목록·문구·프롬프트 등 데이터 변경 | `[내용] 위로가 필요할 때 추천 도서 3권 추가` |
| `[문서]` | README, 안내 문서 변경 | `[문서] 커밋 메시지 규칙 추가` |
| `[정리]` | 동작은 그대로, 코드 구조만 정리 | `[정리] 관리자 패널 코드를 파일 2개로 분리` |
| `[설정]` | 패키지, 빌드, 환경 설정 변경 | `[설정] Vite 버전 업데이트` |
| `[배포]` | 버전 올리기, 아티팩트 반영 | `[배포] 마음결 AI 책방 v1.11` |

## 3. 작성 원칙

1. **한국어로** 씁니다. (코드 이름·파일명은 그대로 영어 가능)
2. **결과 중심**으로 씁니다. "코드 수정" ❌ → "추천 책이 안 뜨는 문제 해결" ✅
3. **한 커밋 = 한 가지 변경.** 서로 다른 작업은 커밋을 나눕니다.
4. 제목 끝에 마침표를 찍지 않습니다.
5. 버전이 바뀌면 제목에 버전을 적습니다. 예: `[배포] 마음결 AI 책방 v1.11`

## 4. 좋은 예 / 나쁜 예

| 나쁜 예 | 좋은 예 |
|---|---|
| `update` | `[수정] 관리자 로그인 후 화면이 멈추는 문제 해결` |
| `fix bug` | `[수정] 위기 키워드 입력 시 안내 문구가 안 뜨는 문제 해결` |
| `여러가지 수정` | 커밋을 나눠서 각각 작성 |
| `feat: add books` | `[내용] 감정별 추천 도서 5권 추가` |

## 5. 업데이트 확인하는 법

1. 저장소 첫 화면에서 **Commits** (시계 아이콘)를 누릅니다.
2. 날짜별로 커밋이 묶여 보입니다. 각 줄의 **[분류]** 와 요약으로 무엇이 바뀌었는지 확인합니다.
3. 자세한 내용은 커밋을 눌러 본문과 바뀐 파일을 봅니다.

## 6. 템플릿 사용

저장소 루트의 `.gitmessage` 파일이 커밋 템플릿입니다. 아래 명령을 한 번 실행하면 `git commit` 할 때 템플릿이 자동으로 열립니다.

```bash
git config commit.template .gitmessage
```
